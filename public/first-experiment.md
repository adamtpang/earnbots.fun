# First experiment: one paid AI workflow

Status: proposed, no buyer or booked revenue established. Prepared 14 October 2026.

## Offer

Add one AI API workflow to an existing, working Next.js app. Proposed price: $500 fixed fee. Proposed delivery: five business days after scope, repository access, a reproducible development setup and provider access are ready. Confirm feasibility before accepting.

Includes one provider, one input-to-output user flow, server-side credentials, input/output validation where appropriate, loading and failure states, critical-path tests and handoff instructions. One revision within agreed scope. Excludes a new SaaS, custom model training, major migrations, regulated-data processing and ongoing support. The buyer funds their own provider usage.

## Before execution

Adam confirms the named buyer, agreed compensation, acceptance criteria, payment terms and funding evidence. A listing, favorable conversation or pending application is not an executable assignment. Agents can prepare research and drafts; Adam performs buyer communication and commitments.

Draft intake questions:

- What input should produce what exact output?
- What application and provider are already in place?
- What should happen when the provider times out or returns invalid output?
- Which data may be processed, and which tools are permitted?
- Who accepts the result, in what environment, against which checks?

## Acceptance

1. A representative valid input produces the agreed result in the test environment.
2. Invalid input, missing credentials, timeout and provider failure produce clear errors without leaking sensitive data.
3. Credentials stay server-side and out of logs and version control.
4. Relevant successful and failure-path tests pass; unrelated regressions are checked.
5. The buyer can reproduce the workflow using the handoff instructions.

## What to prepare now

Use existing portfolio evidence to demonstrate schema validation, streaming and usable interfaces. Prepare a synthetic sample input/output and a failure example. Draft a targeted brief for ten plausible buyers from public evidence, without sending messages. Track confirmed conversations separately from inferred demand. No ads, proposal credits or new subscriptions are required for this preparation.

## Stop and learning rules

If ten qualified, manually conducted conversations produce no willingness to pay, revise the buyer/problem/offer before building a larger system. Ten is an experiment threshold, not statistical proof. If scope exceeds one workflow, narrow or reprice before accepting. If direct costs would exceed receipts, pause before spending. Do not treat a successful test or completed patch as collected revenue.

Continue after an accepted, paid delivery with complete cost records. Seek another independent buyer for the same offer before claiming repeatability. Package a reusable template or tool only where ownership permits and repeated paid needs support it.

## Private measurement

Record actual receipts, refunds, platform/payment fees, direct model/tool costs, owner time, revisions, verification failures and repeat-order interest. Keep receipts and client details private. Compare net cash and owner time across attempts, not task volume or agent count.
